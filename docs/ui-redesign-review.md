# SmokeNotes Web redesign review

Base: `5e669b2278a42733baaf3126b0b9c4472b8b732e` (main when work began). Branch: `codex/smoke-notes-ui-redesign`. Review covers the entire branch, including the initial `5f27093` presentation checkpoint. PR #1 is separate and untouched.

## Implemented design

The web application now uses a warm ivory canvas, heavy sans-serif headings, lilac overview/progress cards, near-black capture cards, lime actions, large rounded cards, subtle shadows and a black floating capsule dock. The notebook browser uses real existing notebooks in lilac/lime/white/black stacked cards, with an accessible expand/collapse control. Todo progress turns soft green at 75%; completion feedback is announced only after a successful update. Failed completion writes retain the task and show an error; duplicate pending toggles are blocked.

Parent-verified video values: ivory `#FBFAF8`, black `#111111`, lilac `#C4BBFE`, lime `#D4E73E`, orange `#FF6825`, completed progress `#C5E882`. Orange/time wheels/timers were not imposed on unrelated note operations. The reference's narrow mobile layout is adapted to a persistent desktop notebook sidebar and two-column note cards. Desktop keeps the overview/capture cards; mobile goes directly to the existing note list. Mobile progress is a small lilac/green badge alongside the heading. The labelled black dock has a reserved area below the content viewport. No scrolling animation loop or new motion dependency was added.

Reference evidence was the parent's direct video inspection and supplied measurements. Library metadata for the seven reference screenshots was accessible, but their image-byte downloads failed in this execution environment. Therefore this is a reference-led adaptation, not a claimed pixel-for-pixel comparison of those source images. Actual implemented desktop/mobile screenshots were visually inspected here.

Alignment QA checked common content edges, card padding, title baselines, icon/text gaps, navigation pill balance, card proportions, dialog margins and compact editor height. Small optical offsets apply only to the up-right arrow and notebook icon. A reduced-transparency theme conflict found in screenshot review was fixed by removing legacy dark glass overrides. Compact touch editing now uses the full width and a shorter header, preserving the same editor instance.

No applicable repository AGENTS.md or local engineering/design SKILL.md was found. When cloud skills were available, the Library and React best-practices skills were read; the static single-file preview skill was inspected and excluded because this is a multi-file repository project.

## Mobile adaptation and interaction acceptance

The exact pre-redesign commit was built in a separate temporary checkout, using only the same isolated sample-data entry, and its actual 390px notes/todo/editor screenshots were compared with the first redesign. The first redesign placed a 220px overview/capture carousel before the notes, enlarged cards and used an overlapping icon dock: about one complete note was initially visible instead of the old layout's three. The large todo progress card similarly displaced the task list. This was a mobile layout problem, not a request for additional visual effects.

The mobile breakpoint now opens directly on compact note cards, retains the header create menu and original single-tap editor flow, and uses a small progress badge next to the todo heading. Every dock item has a persistent label and a reserved navigation area; content stops above it even at the end of the list. The desktop presentation is unchanged: six 1440px screens were visually compared with the preceding redesign using deterministic sample IDs. Five were pixel-identical; the stacked screen differed only in a few rasterized pixels at the dock edge, with no layout/content difference. Note delete/drag handles, todo completion/delete and navigation controls have 44px touch targets; checklist controls are 24px within larger labels. Long notebook headings are limited to two lines with the full accessible name preserved. Inputs used for todo editing/composition use 16px text.

Web browsing positions are remembered per notebook and todo filter for the current app session, so opening a note and returning or switching tabs no longer jumps back to the beginning. The notebook browser retains its expanded/collapsed state, and todo filters persist across navigation. This is in-memory UI state only: no stored record, schema, sync contract or authentication changes. The scroll handler writes refs, without rendering on every scroll.

`tools/review-mobile-ux.py` uses fresh touch-enabled Chromium contexts at 320×568, 360×640, 390×844 and 430×932. Acceptance covers new note → title/body edit → explicit save → return → reload; checklist change → automatic save on return; tab and notebook selection/scroll continuity; stack expansion/collapse and correct notebook identity; todo completion feedback and filter retention; long names; empty-notebook creation; deleting every example notebook and creating again from its empty state; actual emulated touch dragging without opening/deleting a note; delete without opening the editor; immediate undo and restoration through Recently Deleted. The original `tools/review-web-ui.py` additionally checks compact synthetic keyboard viewports, draft retention, offline editing, failure-safe unit regressions, themes, keyboard ordering and reduced motion.

Error behavior is exercised in repository-backed component regressions: duplicate pending saves/completions are blocked, failed saves retain drafts and expose retry, and a failed completion does not announce success. These tests do not simulate a successful cloud sync. Live hosted authentication/multi-device sync and physical iOS/Android keyboard behavior remain untested. Every browser mutation uses disposable example databases; no real user data is involved.
