# 跨设备便签冲突修复与发布 · 0.1.8

当旧设备还未拉取另一端的新版本就编辑时，原实现仅依据版本号差异生成冲突副本。0.1.8 对相同内容进行去重，并记录新操作所基于的便签内容，用于合并两端修改不同字段的情况，例如一端改颜色、另一端改正文。内容比较不受 JSON 对象键顺序影响，仍区分富文本格式和待办状态。

双方修改同一字段且结果不同、删除与编辑并发，以及无法确定修改基础的旧版操作，继续保留冲突副本。已有副本不自动删除。合并结果使用新的操作 ID 和最新服务端基础版本上传，避免复用服务端缓存的冲突响应；上传期间的新编辑也保留。

未改变内容的保存不再增加便签版本。窗口获得焦点、页面重新可见或网络恢复时立即启动同步，减少使用旧版本编辑的机会。
