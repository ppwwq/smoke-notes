# SmokeNotes interaction map

This revision preserves capabilities and data behavior, not the previous screens, control positions or operation paths. The verified video remains the visual reference: ivory canvas, strong black typography, lilac/lime/black surfaces, rounded cards and restrained motion.

| Preserved function                                                                                 | Redesigned entry and behavior                                                                                                                                                                      |
| -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Open and create normal/checklist notes                                                             | Note cards open directly; the primary create action opens the two existing note types.                                                                                                             |
| Notebook create, rename, select, reorder and delete                                                | Notebook collection handles selection; its management entry opens a focused management panel. Per-notebook secondary actions are grouped.                                                          |
| Note and todo manual ordering                                                                      | Explicit Organize mode reveals existing pointer, touch and keyboard drag handles. Done exits the mode.                                                                                             |
| Note/todo deletion                                                                                 | Per-record More opens secondary actions; soft delete retains immediate undo and Recently Deleted recovery. Failed actions retain content and report errors.                                        |
| Title/body editing and autosave                                                                    | Content begins immediately below the editor header. Existing autosave, IME, conflict and draft protections are reused. Local-save status stays visible and is not presented as cloud-sync success. |
| Explicit save and save-before-return                                                               | Visible save action and back action reuse the existing serialized flush; failed saves keep the editor/draft open.                                                                                  |
| Six note colors                                                                                    | More → Note appearance opens a named color panel with a selected indicator and preview. Note color is separate from text/highlight colors.                                                         |
| Bold, italic, underline, strike, checklists, text colors, highlights, clear-color actions and undo | Format expands the existing editor commands on demand; selection/editor instance survive opening and closing. Existing keyboard undo remains available.                                            |
| Todo create/edit/complete/reopen/filter                                                            | Task creation and completion remain direct; filters persist across navigation; success feedback follows successful local persistence only.                                                         |
| App themes and reduced transparency                                                                | Settings → Appearance. Existing browser-local preferences remain unchanged.                                                                                                                        |
| Pairing and sync status                                                                            | Settings → Sync opens the existing pairing flow. Local-save status and sync status remain distinct; unavailable configuration is reported truthfully.                                              |
| Deleted records                                                                                    | Settings → Recently Deleted, with counts and explicit restore actions.                                                                                                                             |
| Keyboard/mobile accessibility                                                                      | Named triggers, focus return, Escape dismissal, touch targets, safe areas and compact viewport editing remain part of acceptance.                                                                  |
| Offline/auth/backend/native desktop contracts                                                      | Existing repositories, IndexedDB schema/keys, cloud/auth logic, service worker and native desktop capabilities remain unchanged.                                                                   |

Research supports progressive disclosure, not removing capabilities: [Google Keep](https://support.google.com/keep/answer/6191044?co=GENIE.Platform%3DAndroid&hl=en) places note color/background behind its Action menu; [Notesnook](https://notesnook.com/help/organizing-notes/organize-notes-using-colors) uses an Assign color action; [ColorNote](https://www.colornote.com/faq-question/how-can-i-filter-notes-by-color/) opens a color-filter dialog from one icon. SmokeNotes distinguishes three tasks: note appearance, text formatting, and application appearance.
