# 烟笺开机自启动设计

## 目标

在桌面版“设置与同步”中加入“开机时启动”开关。用户开启后，登录 Windows 时自动启动烟笺并显示主窗口；关闭后立即取消登录启动。

## 范围

- 默认关闭，不替用户自动启用。
- 仅安装后的 Windows 桌面版写入系统登录启动设置。
- 开发模式不写入启动项，避免把 Electron 开发命令注册到系统。
- 不增加“静默启动到托盘”选项；登录启动后直接显示主窗口。
- 不改变现有关闭到托盘、窗口置顶、透明度或便签恢复行为。

## 交互

“设置与同步”的“窗口”分组新增“开机时启动”开关，并用简短说明标明“登录 Windows 后自动显示主窗口”。打开设置时读取 Windows 当前的真实状态，而不是只依赖应用内缓存。

用户切换开关后，界面调用桌面桥接接口更新系统设置，并以系统返回的实际状态刷新开关。若更新失败，开关恢复到此前状态，避免界面显示为已启用但系统未启用。

## 技术设计

Electron 主进程通过 `app.getLoginItemSettings()` 读取状态，通过 `app.setLoginItemSettings({ openAtLogin })` 更新状态。渲染进程只能通过预加载脚本暴露的窄接口访问该能力；IPC 仅接受受信任的主窗口调用，并把输入规范化为布尔值。

设置不另外写入 Dexie、窗口状态 JSON 或云端，因为 Windows 登录启动项本身是唯一事实来源。这样可以正确反映用户在任务管理器或 Windows 设置中做出的外部更改。

## 错误与边界

- 非安装版请求返回关闭状态，且不写系统设置。
- 系统调用失败时向渲染进程返回失败，界面保留原状态。
- 启动项不存在、被用户从 Windows 设置关闭或应用被卸载时，不尝试用本地缓存强行恢复。

## 验证

- UI 测试：初次打开读取实际状态；点击可开启或关闭；调用失败时回退。
- 主进程测试：仅安装版允许设置；布尔值正确传递；非受信任窗口被拒绝。
- 类型检查与现有完整测试套件通过。
- 重新构建 Windows 安装包。
- 人工验收：安装后开启开关，注销或重启并登录，确认烟笺主窗口自动显示；关闭后再次登录，确认不再启动。

自动化检查不能替代最后一项真实 Windows 登录验收；若本次无法实际重启，会明确把它列为待验收项。
