# 烟笺玻璃材质调研与实施计划

> **For agentic workers:** 后续获准实施时，使用 superpowers:executing-plans 逐项执行下列复选框。本文件是调研后的方案草案，不代表视觉方案已获确认或实现已经完成。

**Goal:** 为「签 / Smoke Notes」Windows 桌面版及手机网页版提供接近 iPhone 观感的玻璃材质，同时保持长文阅读、编辑和便签窗口交互可靠。

**Architecture:** 两端共用 CSS 材质和外观偏好，网页依靠页面内真实背景产生模糊。Windows 系统背景材料单独做可行性验证；只在兼容现有窗口行为后接入。液态折射属于独立增强实验，不作为基础体验的前提。

**Tech Stack:** 当前 React、TypeScript、CSS、Electron 44.0.0、Vite/PWA、现有 Vitest 与浏览器验证工具。第一阶段不引入玻璃组件库、WebGL 或原生二进制依赖。

调研日期：2026-09-18。范围已由用户确认为桌面版＋手机网页版；视觉强度目前按“毛玻璃为底、局部液态高光”的推荐方案拟定。

## 1. 结论与备选方案

**推荐 B：内容区稳重、操作区清透。** 保留烟笺的便签颜色和编辑布局，以磨砂衬底保证阅读，在导航、工具栏、菜单和弹窗上增加玻璃边缘、柔和反光及短暂的按压反馈。

| 方案                    | 观感                                     | 实现与维护                                  | 适用判断                       |
| ----------------------- | ---------------------------------------- | ------------------------------------------- | ------------------------------ |
| A：柔和毛玻璃           | 半透明、背景模糊、轻描边，基本没有形变   | 成本最低，跨端基线较稳                      | 偏阅读、低动效                 |
| B：毛玻璃＋局部液态高光 | 圆润悬浮控件、较通透的边缘、适量交互反馈 | 主要用现有 CSS，可逐步上线                  | **推荐首版**                   |
| C：尽量仿原生液态折射   | 边缘扭曲背景、动态透镜和融合             | Safari 折射路径、实时背景采样和性能都要另测 | 后续独立原型，不能承诺原生一致 |

Apple 的 Liquid Glass 同时涉及背景折射、反射和随交互变化的动态行为；单纯增加模糊不能等同于完整材质。Apple 将它用于浮在内容之上的导航和控件层，并提醒避免把玻璃遍布内容区或层层相叠。详见 [Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) 和[独立 Apple/Web 调研](../../research/2026-09-18-liquid-glass-web-research.md)。

以上推荐是针对本项目的设计判断，不是 Apple 对烟笺的现成规范。

## 3. 技术事实与边界

### 网页内的毛玻璃

`backdrop-filter` 处理元素背后的页面内容；背景需要透明或半透明才能看到效果。若下面只是单一深色，增大 blur 不会凭空产生复杂的玻璃层次。层叠、裁切、祖先透明度和 backdrop root 也会影响采样范围。参见 [MDN backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/backdrop-filter)。

计划使用 CSS blur、saturate、透明色和静态高光建立通用版本；旧 Safari 同时保留 `-webkit-backdrop-filter`。支持声明的检测只能确定属性是否被接受，不能证明具体 SVG 滤镜有正确视觉输出。

### 桌面后方应用的模糊

Electron 官方明确：CSS 模糊仅处理窗口网页内容，无法直接模糊窗口后方其他应用。见 [Custom Window Styles](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)。

Electron 提供 `backgroundMaterial` / `setBackgroundMaterial`，Windows 要求 11 22H2 及以上。当前项目未调用它。见 [Electron BaseWindow](https://www.electronjs.org/docs/latest/api/base-window#winsetbackgroundmaterialmaterial-windows)。

- **Mica** 主要采样桌面壁纸，适合长驻窗口背景；不能把它描述为后方应用的实时模糊。见 [Microsoft Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica)。
- **Acrylic** 更接近磨砂，微软建议主要用于临时表面。系统透明度设置、节能、硬件和窗口状态可能触发纯色降级。它是候选能力，不是默认适用于整张长驻便签的结论。见 [Microsoft Acrylic](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic)。

`transparent: true`、原生材料、透明侧签通道、圆角和鼠标穿透能否同时满足需求，必须独立验证。单纯调用成功不算验证通过；材料还可能覆盖整个矩形窗口而填满透明通道。

### iPhone 上的“液态”

原生 SwiftUI / UIKit 的玻璃 API 不可直接用于本项目的 DOM 界面。Web 可模仿其层次和动效，但不能据此承诺系统相同的光学合成。

Safari 的 SVG 背景滤镜引用仍存在实现缺口，首版不依赖 `backdrop-filter: url(#...)`。状态随浏览器版本变化，进入折射实验前再次核实并在目标 Safari 真机测试。证据及版本细节见[Apple/Web 调研](../../research/2026-09-18-liquid-glass-web-research.md)。

## 4. 拟定视觉与交互规范

| 区域                           | 首版处理                                                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------- |
| 手机底部主导航                 | 两入口保持，改为有边距的圆角浮层；使用页面内滚动内容作为背景；为最后一项内容预留足够底部空间 |
| 手机编辑顶栏、格式浮层         | 更轻的磨砂、高光描边；尊重软键盘和横屏精简模式；控件不依赖 hover                             |
| 桌面主窗工具区、设置弹窗       | 适度模糊、统一圆角和衬底；原生窗口底材另行验证                                               |
| 独立便签顶栏、菜单             | 与正文分层，增加细亮边；装饰层 pointer-events:none                                           |
| 长文正文、便签列表             | 保持稳定文字对比；不用折射扭曲文字，不给每张卡片独立大面积模糊                               |
| 网页纸面模式                   | 使用原有纸色与正文横线；不应用玻璃材质，切回默认背景后恢复所选材质                           |
| 同步二维码、字体颜色与荧光标记 | 保持原有功能和识别度；单独核验透明层是否降低辨识                                             |

初始调参范围属于本项目候选值，不是官方标准：

- 导航及工具栏 blur 16–24px，移动端从 16px 起；饱和度约 115%–140%。
- 窄控件圆角 14–20px，主导航使用胶囊形轮廓；窗口尺寸与侧签几何不随之变化。
- 边缘 1px 柔和亮线；高光层低透明度；取消持续流动的装饰动画。
- 按压缩放约 0.98，过渡约 140–200ms；仅作用按钮表面，避免对编辑根节点或固定导航祖先整体 transform。
- 背景透明度通过背景层色值／现有背景变量实现，文字所在父级不降低 opacity。
- 浅色、深色、高频图片、长文滚动作为共同对照；如果提高通透度后文字不稳，优先提高衬底覆盖率。

## 5. 外观偏好与降级

建议在设置加入“玻璃效果”：**原有外观／柔和毛玻璃／液态质感**，并提供“减少透明效果”开关。首版默认保留当前外观，用户主动选择新效果；是否最终成为默认外观在原型评审后决定。

现有网页“背景：默认／纸面”继续负责配色和纸张主题；玻璃效果只负责材质。在纸面模式中材质选择暂不可用并显示“纸面模式使用实色背景”，但保留选择。桌面材质偏好不影响每张便签的背景透明度数值。

拟定最小数据契约：

```ts
type GlassMode = "legacy" | "frosted" | "liquid";
type GlassPreference = {
  mode: GlassMode;
  reduceTransparency: boolean;
};
```

只存本地，不写便签数据或云端同步队列。主窗和独立便签在本机共享；网页偏好只作用当前站点。沿用 localStorage，以 `smoke-notes:glass-preference:v1` 为新键，验证值、读写异常和跨窗口事件。不迁移、不覆盖现有 `smoke-notes:web-background`。

主窗与便签开发时同源，打包后加载相同文件不同查询参数；打包环境 localStorage 共享和事件传播需要实测。若只是不即时刷新，先保证下次打开读取正确；若确实不共享，再决定是否用现有 DesktopBridge 增加本地 IPC，不能预先引入两套存储。

处理优先级：

1. 纸面主题使用纸色实底。
2. 应用“减少透明效果”、系统减透明（浏览器能报告时）、强制颜色模式优先于材质选择。
3. 无 backdrop 支持时显示足够不透明的底色、描边和静态阴影。
4. 有支持时按所选材质渲染。
5. 系统减少动态效果独立处理：保留操作反馈，关闭形变和移动高光。

保留人工开关是因为各浏览器对系统减透明偏好的支持不同。截至调研日，Safari 在 [MDN 兼容数据](https://github.com/mdn/browser-compat-data/blob/main/css/at-rules/media.json) 中尚不支持 prefers-reduced-transparency。网页纸面本已提供实色路径，但桌面没有纸面模式，网页用户也可能希望保留深色配色，因此需要共享的减少透明开关。该开关在“原有外观”模式下同样生效。系统设置检测不到时，不能当成用户确认愿意接受透明效果。
